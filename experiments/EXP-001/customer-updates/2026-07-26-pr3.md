## What changed

The HP ZBook utility now uses short customer-facing commands: `Check`,
`Benchmark`, `Tune`, `FullTest`, `Compare`, `Undo`, and `RestartTest`.
Management detection no longer mistakes the generic Microsoft
`MDMMaintenenceTask` for an active MDM enrollment when domain join, Entra join,
MDM URLs, and enrollment-specific tasks are absent.

Benchmark JSON now identifies itself as `PreProtocolScreening` and sets
`FormalBaselineEligible` to `false`. Aggregate and comparison records reject
unclassified inputs. Automatic `Compare` selection skips legacy files and
restart-test records so they cannot be relabeled as tuning evidence.

The one-time restart workflow captures its original Winlogon state, uses an LSA
secret rather than a plaintext `DefaultPassword`, and requires a matching,
integrity-valid recovery record before cleanup can run. Cleanup is not reported
as successful until the secret is absent, captured Winlogon values match their
original state, and the resume task is gone.

## Supported configuration

This build is locked to the lab configuration below:

- HP ZBook Firefly 14 inch G8 Mobile Workstation PC
- Intel Core i5-1145G7
- Windows 11 Pro build 26200
- BIOS T76 01.24.02

`Check` and `Benchmark` remain read-only. Changing actions stop outside this
support lock. Battery/DC power values are preserved.

## Services, tasks, drivers, firmware, and OEM software

- No Windows or HP service was stopped, disabled, or reconfigured.
- No update, security, management, or HP support task was disabled.
- No driver, BIOS, firmware, graphics mode, or HP performance profile was
  changed.
- The optional restart workflow can create one temporary resume task, but that
  state-changing path has not been executed in the recorded lab evidence.
- HP Image Assistant remains an analyze/report-only research option. HP Support
  Assistant, HP Wolf Security, Windows Update, Defender, BitLocker, Secure Boot,
  and management controls are preserved.

## Documented facts

- Microsoft documents the processor power-management settings and the
  `PowerReadACValueIndex` API used to read current AC/DC values.
- Microsoft documents that automatic logon creates physical-access risk and
  that an LSA secret can protect the password from the Winlogon plaintext value.
- HP's support information is model-dependent. Firmware, driver, graphics-mode,
  and HP performance-control availability cannot be generalized across all
  ZBooks.
- System Restore protects monitored system state; it is not a full disk or
  personal-file backup.

## Lab measurements

- The recorded lab configuration matched the exact model, processor, Windows
  build, and BIOS support lock.
- Sixteen of the 17 selected settings already matched before the first
  transaction.
- The AC energy-performance preference was the only setting varied during the
  recorded apply/rollback/crossover work. Exact rollback and reapply
  verification passed.
- Mixed crossover screening found no value that improved every synthetic
  metric. The selected general configuration therefore retains value `33`.
- All static and non-destructive integration tests passed after the final merge.

These measurements are preserved screening observations. They are excluded
from formal workflow medians and do not establish a customer performance gain.

## Hypotheses

- Some visual preferences may improve perceived directness without materially
  changing measured application readiness.
- More aggressive AC processor behavior may help sustained CPU work while
  increasing heat, fan activity, and energy use.
- Firmware and HP/Intel thermal control may dominate or override requested
  Windows power values.

These are hypotheses, not accepted findings.

## Unresolved questions

- Reboot persistence and one-time auto-login cleanup have not been executed on
  the physical lab machine.
- The nine customer workflows do not yet have complete deterministic probes,
  instrumentation-overhead qualification, or seven valid repeated runs.
- Thermal, fan, AC-energy, and battery impacts remain unmeasured.
- Direct Microsoft support coverage remains incomplete for some per-user
  registry interfaces represented by the current UI allow-list.
- No service-stop candidate has yet met the dependency, support, measurement,
  and rollback gates.

## Backup and rollback

Before a changing action, the tool captures typed original registry values,
original AC/DC power indices, the active power plan, registry exports, a power
plan export, and a SHA-256-protected manifest. It attempts a restore point and
verifies apply and rollback. A compliant re-run is idempotent and creates no
new backup or write.

This is exact rollback for the allow-listed settings, not a guarantee against
disk, firmware, or unrelated system failure.
